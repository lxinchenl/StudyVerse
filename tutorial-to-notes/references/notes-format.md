# 笔记输出格式规范

最终 docx 笔记必须严格遵守以下格式。字体、字号、层级、例子规范是质量门，不可自行偏离。

## 页面设置

| 属性 | 值 |
|------|-----|
| 纸张 | A4 (21.0cm x 29.7cm) |
| 页边距 | 上下 2.54cm，左右 3.18cm |
| 行距 | 正文 1.5 倍行距，标题单倍行距 |

## 字体规范

| 内容类型 | 字体 | 字号 | 备注 |
|----------|------|------|------|
| 中文正文 | 宋体 (SimSun) | 12pt (小四) | 同时设置 `w:eastAsia` 属性 |
| 英文/数字 | Times New Roman | 12pt | 与中文混排时 run 级别控制 |
| 代码/SQL | 楷体 (KaiTi) | 12pt | 全文保持一致 |
| Heading 1 | 宋体 + Times New Roman | 18pt | 加粗，居中 |
| Heading 2 | 宋体 + Times New Roman | 15pt | 加粗，左对齐 |
| Heading 3 | 宋体 + Times New Roman | 13pt | 加粗，左对齐，缩进 0.75cm |

## 四级层次结构

```
主题 (Heading 1, center, 18pt)
  └ 子主题/方法 (Heading 2, left, 15pt)
      └ 具体方法/分类 (Heading 3, left, 13pt, indent 0.75cm)
          └ 要点、例子、流程 (Normal, 12pt, indent 1.5cm)
```

缩进规则：
- Heading 1/2：无缩进
- Heading 3：左缩进 0.75cm
- Normal 要点：左缩进 1.5cm，首行无缩进

## 段落模板

| 类型 | 格式 |
|------|------|
| 定义 | `概念：一句话本质` |
| 分类 | `分为：A（XX）、B（XX）` |
| 流程 | `流程：Step1 → Step2 → Step3` |
| 图信息 | `【图】XX描述` |
| 优缺点 | 行内，`优点...，缺点...` |
| 例子 | `例：具体示例内容`，另起一行或跟在概念后 |

## 例子规范

每个核心定义 / 分类 / 流程条目后必须跟一个具体例子。

- 格式统一：`例：` 前缀
- 来源优先级：教材例题 > 教材插图说明 > 教材SQL语句 > agent 自构造
- SQL 章节：每个语法结构必须配可执行的 SQL 例子
- 例子位置：跟在所属概念后可另起一行，也可行内用 `——` 分隔

正确示例：
```
视图 - 从一个或几个基本表导出的虚表，只存放定义不存放数据
例：CREATE VIEW IS_Student AS SELECT Sno, Sname FROM Student WHERE Smajor='计算机科学与技术'
```

## 高亮规则

仅用于最重要的 2~5 个核心概念或公式，使用黄色高亮（w:highlight w:val="yellow"）。

典型适合高亮的内容：
- SQL 完整语法格式
- 全称量词等价公式 (∀x)P ≡ ¬(∃x(¬P))
- LIKE 通配符规则
- 视图消解原理等

## 禁止项

- ❌ 不要用 Markdown 标记输出（如需样例可临时用 md，最终交付必须是 .docx）
- ❌ 不要用表格、彩色、emoji、装饰边框
- ❌ 正文不要加粗/下划线（仅标题行用加粗）
- ❌ 不要写完整句子，用要点/条目形式
- ❌ 不要用 Unicode 数学符号（用 LaTeX → OMML 管线或文字描述）
